# Проверки 0.2, 2026-10-07

Это результат разработки и офлайн-проверок, не приёмка качества игрового бота.
OpenTDM-X DLL/SO, серверы и работа Claude над q3t2 не изменялись.

## Реальные данные и обучение

Текущий порядок: q2duel5 + ztn2dm3; q3t2 — после завершения Claude;
q2duel1 — после q3t2 с учётом телепортов. В обучение 0.2 вошли только первые
две карты. Архивы будущего q2duel1 не распаковывались для обучения.

Первый эксперимент использовал подготовленный корпус: 7 672 158 строк,
по 2000 последовательностей в train/validation/test. Затем сквозной импорт
из исходных файлов дал 41 запись q2duel5 и 14 ztn2dm3, 292 622 строки.
На втором наборе train содержит 25 групп пар соперников, validation — 3,
test — 2. Повторные POV известной пары удерживаются в одной части. Это
не сертификация личности по всем возможным псевдонимам; малое число
независимых тестовых групп ограничивает обобщение результата.

Compact, CUDA, история 16 кадров, 20 эпох, выбор поколения по validation:

| Карта | Ошибка скорости на test, ед./с | Продолжение текущего движения |
|---|---:|---:|
| q2duel5 | 130.64 | 160.01 |
| ztn2dm3 | 145.09 | 172.38 |

Предсказания оружия/ресурсов/близости предмета не превзошли свои простые
базовые сравнения. Их нельзя считать обученной тактикой. Экспорт включает
только прошедшие validation непрерывные выходы движения и смещения.

При последовательном обучении q2duel5 → ztn2dm3 простой replay ухудшил
старое предсказание маршрута; кандидат был отклонён. После добавления
сохранения предсказаний прежней модели и отбора эпох с учётом удержания
старого навыка дообучение прошло оба ограничения: +1% по скорости и +3%
по смещению. Это ограничения наблюдательных метрик, не счёта матча.

## Физика, импорт и приложение

- Отдельный native build: декодер и physics.dll; игрового модуля в сборке нет.
- Реальная MVD2 ztn2dm3: 54 593 состояния, карта определена из записи.
- Обычные маршруты: q2duel5 — 633 узла / 3776 направленных проверенных связей;
  ztn2dm3 — 1101 / 5113. Условия — статическая геометрия и начальные остановки платформ.
- На триксовой z3.dm2 проверены 219 интервалов; 192 коротких соответствия.
  Из 26 кандидатов по 1,6 секунды четыре прошли непрерывный replay без
  возврата к записанным координатам, два содержат прыжки. Это ещё не все
  триксы записи. Добавлен шаг 7 мс, но смешанный реальный cadence, RJ-импульсы
  и динамические платформы остаются отдельными задачами квалификации.
- 25 автоматических тестов: целостность, разделение выборок, архивные пути,
  блокировки, отмена после фиксации, непрерывное/возобновлённое обучение,
  пакеты и откат. Возобновление даёт побитно те же веса на CPU.
- Desktop собран без ошибок/предупреждений; 28 снимков RU/EN × light/dark ×
  семь страниц, просмотрены основные страницы. Process bridge проверен
  со встроенным CPython 3.13.16/PyTorch 2.10 CPU без системного Python.
- Подготовлены встроенные CPU и CUDA-среды, импорт библиотек прошёл.
  Устройства AMD/Intel и чистая отдельная Windows-машина не проверялись.
- Калибровка XL/128 на RTX 5090 прошла forward/backward/update при batch 1024;
  пик выделенной памяти тензоров около 8,43 GiB. Это не полная память процесса,
  не минимальное требование и не оценка игрового качества.

## Незакрытые задачи

Полноценные тактические цели и причинные метрики боя; терминальные участки
со смертью вместо отбора только выживших; восстановление всех важных триксов;
динамические платформы, RJ-импульсы и будущие телепорты; баллистика с
рикошетами, проверенная против игровых снарядов; обзор/уточнение личности
донора в GUI; управляемая установка AMD/Intel-сред; более широкие holdout;
универсальный загрузчик знаний в моде и реальные матчи после согласования.

Пока нельзя заявлять «обучено играть на новой карте», «скопирован весь стиль»
или «готовый серверный пакет». Формат `bts-knowledge-candidate-v1` явно имеет
`runtime_qualified=false`, `server_installable=false`.
